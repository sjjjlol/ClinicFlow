# 隔离故障实验

正常应用不包含这些缺陷。L1/L3使用独立`clinicflow_labs`数据库；L2启动临时本机HTTP服务和临时SQLite文件，退出时清理。只对生成的虚构数据操作。先启动项目MySQL：`docker compose up -d --wait db`。每次运行自动重建本实验表，就是重置命令；不会清除正常应用数据。

## L1 并发覆盖

运行 `./scripts/labs.sh L1`。两个独立连接通过屏障读取同一v1，A先写入，B随后以旧快照写入。观察两次affected都是1，A的数据消失。检查SQL是否把读取时的Version用在写入条件；假设“最后写入成功就正确”是否成立？

任务：使过期写入得到可解释冲突，只接受一个修改。验收：固定顺序下A成功、B冲突，最终版本只递增一次；正常测试A08继续通过。记录读/写时间线、SQL与affected rows，不靠手速重现。

## L2 重复外部处理

运行 `./scripts/labs.sh L2`。第一次HTTP请求在接收端提交后断开，客户端使用同一MessageId重试。观察投递2次、持久副作用2次。检查“请求超时”能否说明远端未处理；想象副作用是通知事件，而不只是覆盖相同状态的PUT。

任务：使去重记录与效果原子保存，并允许响应丢失后的重放。验收：两次投递只产生一个效果；正常接收端A14的重启测试继续通过。正常接收端的持久性边界见Integration ADR。

## L3 慢查询

运行 `./scripts/labs.sh L3 100000`（范围1000–1000000行）。同一参数查询在无组合索引与增加索引后各执行5次，记录EXPLAIN ANALYZE、计时中位数、机器信息。脚本强制检查排序后的结果ID相同。重复运行会重建实验表；选择数据量后固定它再比较。

任务：先分析筛选、排序和分页需要的索引顺序；解释扫描行数和排序，而不是只看耗时。验收：有执行计划支持，结果集合/排序/分页保持一致，不预设性能提升百分比。证据在docs/evidence/L3-plan.txt，不能作为企业生产收益。

完成分析后再阅读 [解析](solutions/analysis.md)。独立Completed需求仍保留给用户，本目录没有实现该需求。
