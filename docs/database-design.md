# OIS 数据库

<a id="ois-data"></a>

|表|用途|
|---|---|
|Patients|共享患者资料，保留虚构种子患者|
|Users|三个工作人员角色及密码散列，不再绑定个人患者账号|
|Idempotency|命令指纹和原始成功响应，保留已有请求重放能力|
|CareCase|患者诊疗档案及当前处方/计划引用|
|Prescription|签署处方和修订链|
|TreatmentPlan|外部计划版本、处方版本、机器、审核和验证结论|
|OisResource|诊疗人员和机器资源、可用性|
|Reservation|单次门诊、治疗、实验和维护占用|
|TreatmentDelivery|实际使用的计划版本、执行结果|
|OisTask|责任角色待办、已读和处理结果|
|OisAudit|操作者、变更内容、请求关联号及时间|
|OisGate|所有 OIS 写事务先获取的排他行锁|

具体字段和索引以 `backend/Ois/Models.cs` 及模型快照为准。患者及计划关联受约束，签署历史不覆盖；版本校验、半开区间冲突和角色规则由服务端统一执行。

## 从现有版本升级

历史 EF 迁移保留，以兼容已经应用迁移的数据库；它们不是旧业务模块。新的 `RemoveLegacyModules` 迁移删除旧预约、槽占用、前置任务、审计、资源、Outbox、同步尝试及影像关联表，删除非 Scheduler/Clinician/Physicist 账号和 Users.PatientId。

保留全部患者资料、OIS 九张表、三个工作人员角色账号/密码及幂等表。幂等表不按不透明哈希猜测来源删除记录。清理迁移不会自动把旧预约转换成临床数据。

**启动新版前先备份数据库并停止旧版写入。** 应用启动自动执行迁移；该清理会删除旧模块数据。Down 只能重建空表结构，不能恢复删除的数据；需要完整恢复时使用升级前备份。

`./scripts/upgrade-drill.sh` 在隔离库创建上版 OIS 数据 → SQL 备份 → 清理迁移 → 验证 OIS 数据、账号、审计、幂等重放及旧表删除 → 恢复备份并验证。不会操作应用数据库。
