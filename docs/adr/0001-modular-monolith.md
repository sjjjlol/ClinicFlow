# 三个业务模块保留单体事务

本次将诊疗管理、计划与验证、排程与执行分为三个候选限界上下文，使用明确的数据所有权、只读摘要和模块命令协作；保留单体部署、同库外键和 CommandExecutor/OisGate 的本地事务。处方修订与治疗开始必须互斥，验证失败与停机、待办必须同时生效，当前小规模演示尚无独立扩容或发布需求，直接拆为远程服务会额外引入失效传播与分布式并发协议。

物理验证记录归 Planning，实验时段和预约状态归 Scheduling。迁移把历史签署字段移到独立表，工作台聚合查询继续提供旧响应字段；写入不会跨模块直接修改其他实体。实体 CLR 名称保持兼容旧 EF 元数据，最初暂不拆程序集；现已由 [ADR-0002](0002-layered-events.md) 拆为四层程序集，业务上下文仍通过契约和架构测试约束。

这是模块边界重构，不宣称跨模块事务已经消除。全量加载与单行锁仍限制吞吐量；未来拆服务时，应先设计治疗开始的版本凭据、资源占用、处方/计划失效协议，再设计远程消费者与流程协调机制（本地 Outbox 已按 ADR-0002 实现）。不能仅将同步调用替换成最终一致的缓存读取。
