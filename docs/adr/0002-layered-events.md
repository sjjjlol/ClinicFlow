# DDD 分层程序集与两类事件

状态：已采纳。承接 [ADR-0001](0001-modular-monolith.md) 的模块化单体与同步事务决策，替代其中“暂不拆程序集”的实现安排。

原工程将 Controller、用例、领域对象及 EF 持久化放在一个 Web 程序集中，领域目录无法阻止基础设施依赖进入业务代码。现在采用 Domain、Application、Infrastructure、API 四个项目，Domain 不依赖其他项目，Application 仅依赖 Domain；基础设施实现应用端口，API 通过组合根装配它们。HTTP DTO、应用 Command、工作台响应与实体分别定义。

Clinical、Planning、Scheduling 的业务边界继续保留；四层工程不按部署服务划分。全局 OisGate、同库外键与同步安全检查仍在，避免将处方修订、验证停机与治疗开始之间的一致性变成未定义的分布式协议。

聚合记录领域事件，应用处理器在当前事务内完成联动；集成事件通过显式映射形成独立的 V1 契约，并与业务变更写入事务 Outbox。投递在提交之后进行，采用至少一次语义，消费者须去重。默认未接入真实 publisher 和后台工作者，消息保持待投递，系统不会虚报发送成功。

代价是请求与响应映射代码增加、Outbox 需要积压监控与保留策略；全量读取和串行写入仍是演示限制。未来拆服务需另行决策资源占用、版本凭据、失效协议、有序需求与 Inbox，不能只将现有同步调用替换为消息。
