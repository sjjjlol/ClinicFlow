# 用时间格唯一占用和局部锁替代全局写锁

状态：已实施。替代 ADR-0001、ADR-0002 中的 OisGate 全局写入串行化，保留模块化单体、领域规则和同库事务。

## 问题

全局锁能保护时段检查与跨模块安全条件，但机器 A 的命令会阻塞无关的机器 B。单纯删除锁又会使新预约、机器停用、处方修订和治疗开始出现竞态；Version 无法保护两个不同的新预约。

## 决策

- Reservation 仍是业务记录，Infrastructure 的 ReservationOccupancy 将未取消预约拆为 15 分钟的资源格及可选患者格，复合主键 `(SubjectType, SubjectId, SlotStartUtc)` 防止重叠。维护和实验不占患者格。
- ActiveExecution 用 `(SubjectType, SubjectId)` 主键保护实际正在执行的患者和机器。完成或中断后释放，日历到点不会自动释放。
- OccupancyStore 仅同步本次新增或修改实体的占用，保留共有格，删除旧格，再插入新格。两次 SaveChanges 位于同一事务，新增格冲突也会回滚此前删除、状态、审计、幂等结果和 Outbox。
- CommandLocks 从命令及相关记录解析患者、资源、目标锁，使用数据库中的稳定键，固定顺序获取。锁前查询只用于发现关联，锁后重新解析；关联变化则拒绝本次命令，客户端刷新后重试。
- Idempotency 的唯一请求行先在事务内认领。同键串行核对指纹并重放已提交响应，失败不留半成品记录。历史键和指纹算法不变。
- SchedulePolicy 的区间预检查、角色与版本校验保持不变；数据库占用约束作为最终防线。

## 取舍

同患者、同资源或共享目标仍会排队，资源锁也覆盖机器停用和执行状态，避免只保护时间格。无共享关联的命令能够并行，OisGate 留作历史表但不再用于运行时锁定。

状态仍全量读取；没有新增排班、临时占位、支付、超时释放、自动死锁重试或任意时间粒度。所有非 Cancelled 状态继续保留预约格，与旧区间规则一致。锁键不做在线清理，维护者不得在写入期间删除正在使用的锁行。

扩展命令时必须检查 CommandLocks 是否覆盖它读取和修改的关联，扩展预约行为时必须保证预约与占用在同一事务同步。直接 SQL 只写 Reservation 会绕过占用完整性，本方案没有数据库触发器替代应用写入协议。

## 迁移与证据

SlotOccupancy 迁移先拒绝非法时间、重叠历史预约及重复执行，再建表并回填。升级前停止旧写入和备份，不支持新旧写协议混跑。Down 只删除三张新表，保留业务事实；再次 Up 可重建占用。

SlotOccupancyTests 覆盖唯一约束并发竞争、改期后段失败整体回滚、取消恢复、相邻时间、幂等、独立资源并行、机器停用竞争以及迁移预检/回填/往返。ModuleTransactionTests 继续验证处方修订与治疗开始互斥，并覆盖实际执行占用释放。实际运行记录见[验收](../acceptance.md)，直白讲解见[预约专项](../appointment-design-and-conflicts.md)。
