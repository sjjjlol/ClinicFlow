# OIS MVP — 已确认方案与交付计划

本方案经 2026-10-13 需求讨论确认，是当前项目唯一产品范围基准。后续模块化重构保持此业务范围；代码组织与部署取舍以[架构说明](architecture.md)为准。

## 范围

单院区、多个放疗机器；模拟患者、模拟外部治疗计划和物理验证结果。采用确定性规则和标准日/周日历，不使用 AI Agent。只做单次患者预约，不做疗程批量排期、不计算剂量、不控制真实设备、不解析 RT Plan/RT Dose。

## 用户与权限

|角色|职责|
|---|---|
|Scheduler 预约人员|患者门诊/治疗预约、改期、取消、恢复、未到场登记、受阻预约协调|
|Clinician 诊疗人员|接诊、签署处方、审核计划、安排实验机器与时间、治疗执行、临床退回处理|
|Physicist 物理师|登记外部计划摘要/附件引用与版本、物理实验结果签署、计划修订、设备停用与恢复|

医生与治疗师合并是演示范围简化；同一诊疗账号可以审核和执行，物理验证必须由物理师完成。每个角色有自己的工作台，患者详情共用。系统仅提供这三个工作人员角色，不提供患者自助注册。

## 主流程

门诊预约 → 接诊和诊疗档案 → 诊疗记录与处方 → 外部计划版本登记 → 诊疗审核及物理实验验证 → 单次治疗执行。

患者无需到场参与物理实验，实验不是患者预约，但关联具体患者计划版本。诊疗人员为实验安排机器时段，物理师执行并提交结果。机器占用统一检查，禁止覆盖已有治疗或实验。

允许治疗提前排期。预约成功、当前计划获准治疗、治疗实际完成分别记录。开始治疗时后端重新检查身份核对、当前计划审核和物理验证、机器可用性，并固定实际使用的计划版本。

## 日历与异常

- 门诊冲突：患者、接诊人员；治疗冲突：患者、机器；实验/维护冲突：机器。
- 时间按 15 分钟对齐，使用 Asia/Shanghai 展示、UTC 存储，采用半开区间。
- 改期先预览确认，取消填写原因，恢复需重新检查冲突；提交带版本和幂等键。
- 计划验证失败：保留未来预约，显示受阻，生成责任角色待办。计划问题交物理师修订，处方问题交诊疗人员评估，设备问题停用机器并交预约人员协调。
- 新版本重新审核验证，不继承旧版通过结果。已执行记录保留原计划版本。
- 设备恢复由物理师登记原因，不自动使失败计划通过。
- 已签署信息只可追加更正或产生新版本，不可覆盖删除。
- 预约状态与执行结果分开；到点不自动完成，未到场/中断不自动补约，中断需原因与人工处理。
- 待办包含责任角色、原因、处理结果及已读状态。MVP 不接邮件、短信或微信。

## 页面与数据

三个角色工作台、患者诊疗档案、日/周资源日历、计划版本及验证详情、治疗执行记录、机器可用性与占用、站内待办和审计。

核心对象：患者、诊疗档案、签署记录/处方版本、计划版本、审核、每次实验的独立签署验证记录、资源占用、单次患者预约、治疗执行、待办、追加式审计。

## 验收

1. 正常闭环：门诊 → 处方 → 计划 → 审核和验证 → 单次治疗完成。
2. 预约冲突、并发争用、改期、取消恢复均正确检查并留痕。
3. 验证失败阻止执行，新版独立审核验证后重新放行，历史可追溯。
4. 治疗中断保留原因，进入人工处理待办，不自动补排。
