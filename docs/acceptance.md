# OIS 验收

<a id="current-status"></a>

只验收 [OIS 范围](ois-mvp.md)。测试入口见[运行手册](runbook.md)。

- 规则：双重签署放行、计划修订、患者与机器冲突、取消恢复、版本冲突、验证失败分类、设备恢复、角色约束、中断和人工跟进。
- MySQL：并发单一成功、原子审计、幂等回放、失败回滚、完整失败→修订→放行→中断闭环。
- HTTP：登录/退出、CSRF、角色隔离、计划审核、预约冲突、版本及幂等，旧 API 返回 404，OpenAPI 只暴露 OIS 和认证。
- 浏览器：跨角色处方/计划/审核/实验排期；单次预约预览、取消恢复、日周日历。
- 升级：从清理前 OIS 数据库迁移，验证临床数据和幂等重放保留、旧表及旧账号删除，再验证备份恢复。
- 容器：全新数据库和打包前端启动，完成 HTTP 验证；打包页面测试覆盖根路径、JS/CSS 资源及旧入口 404。

规则测试用可控时钟验证完整执行闭环，浏览器测试不代表真实临床设备验收。历史混合版本的 93 项后端及 18 项浏览器测试数量不再作为当前版本证据。

## 2026-10-16 清理验证

本机已通过：18 项 .NET 测试、3 项浏览器测试、HTTP 认证及 OIS 命令验证、前端构建与格式检查、EF 模型/迁移一致性检查，以及上版 OIS 数据库升级和 SQL 备份恢复演练。测试使用独立 Compose 项目和数据库，未迁移原演示库。


## 2026-10-24 模块化重构验证

本机通过解决方案构建（0 警告、0 错误）、29 项 .NET 测试、EF 模型与迁移一致性检查、HTTP 认证/OIS/Controller 三组回归，以及旧版 OIS 升级和 SQL 备份恢复演练。

新增测试覆盖：模块不持有其他业务模块实体及全局状态、摘要不可修改；处方修订与治疗开始并发互斥；验证签署后故障导致计划、实验预约、停机、待办、审计和幂等结果整体回滚，同 key 可重试；历史验证字段搬移、工作台响应兼容和 Down/Up 数据往返。

.NET 使用 clinicflow_tests，HTTP 使用独立的 clinicflow_ddd_http_tests 和临时演示凭据，升级演练使用 clinicflow_upgrade_tests。没有迁移现有应用库或修改本地 .env。本次未重跑浏览器测试；前端源码和请求契约未改，工作台响应由 ReservationResponse 兼容投影，并经 HTTP 回归验证。

## DDD 分层与事件回归

LayerTests 验证 Domain/Application 的依赖方向和响应 DTO 隔离；ModuleTransactionTests 验证事件联动与数据整体回滚、重放无重复 Outbox；OutboxTests 验证失败退避、稳定事件 ID 和已确认记录不重发。真实消息中间件及消费者未接入，不在当前端到端验收范围。
