# OIS 验收

<a id="current-status"></a>

只验收 [OIS 范围](ois-mvp.md)。测试入口见[运行手册](runbook.md)。

- 规则：双重签署放行、计划修订、患者与机器冲突、取消恢复、版本冲突、验证失败分类、设备恢复、角色约束、中断和人工跟进。
- MySQL：并发单一成功、原子审计、幂等回放、失败回滚、完整失败→修订→放行→中断闭环。
- HTTP：登录/退出、CSRF、角色隔离、计划审核、预约冲突、版本及幂等，旧 API 返回 404，OpenAPI 只暴露 OIS 和认证。
- 浏览器：跨角色处方/计划/审核/实验排期；单次预约预览、取消恢复、日周日历。
- 升级：从清理前 OIS 数据库迁移，验证临床数据和幂等重放保留、旧表及旧账号删除，再验证备份恢复。
- 容器：全新数据库和打包前端启动，完成 HTTP 验证；打包页面测试覆盖根路径、JS/CSS 资源及旧入口 404。

规则测试用可控时钟验证完整执行闭环，浏览器测试不代表真实临床设备验收。历史混合版本的 93 项后端及 18 项浏览器测试数量不再作为当前版本证据。

## 2026-10-25 预约时间格占用重构

本机通过完整 .NET 回归 **43 项**、EF 模型/迁移一致性检查、HTTP 认证/OIS/Controller/资源契约回归，以及旧版升级和 SQL 备份恢复演练。

新增验证覆盖：

- 同一患者或资源的交叠时间格在数据库层只能提交一份，包括绕过应用预检查的并发插入。
- 改期新增格发生数据库冲突时，旧格、预约版本、审计与幂等结果全部回滚；原请求键可以再次提交。
- 取消释放、恢复重建、改期保留共有格、相邻时间衔接、幂等重放无重复格。
- 持有历史 OisGate 锁及机器 A 命令锁时，无关联的机器 B 命令仍可提交。
- 机器停用与预约竞争时，不会丢失已接受预约的受影响待办。
- 开始治疗创建患者/机器执行占用；中断结束后释放执行占用，但保留历史预约格。
- 迁移拒绝非法/重叠历史，回填未取消预约及执行占用，Down/Up 往返保留业务事实。

原处方修订与治疗开始互斥、验证失败联动回滚、历史幂等重放等测试继续通过。旧验证记录迁移测试的三次历史实验夹具改为不同日期，避免使用旧业务规则本就不允许的重叠机器时段。

.NET 使用 `clinicflow_tests`，HTTP 使用独立的 `clinicflow_slots_20261025_tests` 和临时测试凭据，升级演练使用 `clinicflow_upgrade_tests`；未迁移现有应用库，未修改 `.env`。前端源码和 HTTP 契约未改变，本次未重跑浏览器测试。
